# SM-Config-KMS 安全基线（SECURITY BASELINE）

> 服务：sm-config-kms（配置与密钥管理服务）
> 版本：v1.0 ｜ 适用环境：dev / staging / prod
> 编制依据：等保 2.0 三级、ISO 27001:2022、企业内部安全规范

## 1. 安全基线概述

本文件定义 SM-Config-KMS 在容器化部署（Kubernetes）与企业网络环境下必须满足的安全控制项。所有控制项分为"必须（Must）"与"建议（Should）"两级，必须项未通过不得上线生产。

基线覆盖：身份认证、网络隔离、数据加密、容器加固、密钥管理、审计日志、漏洞管理七大领域。

## 6. 认证与授权机制

- **服务间认证**：内部 API Key（`SM_INTERNAL_API_KEY`）经 ExternalSecret 从 Vault 注入，禁止硬编码。
- **用户认证**：对接统一 IAM（SM-IAM），OIDC/OAuth2 标准协议，JWT 令牌有效期 ≤ 2 小时。
- **授权模型**：RBAC + ABAC 混合策略，角色绑定资源范围，属性条件补充细粒度控制。
- **管理面认证**：管理接口仅在企业内网/VPN 后暴露，强制 MFA。

## 7. 审计日志要求

- 审计事件：登录、权限变更、数据导出、密钥操作、配置变更。
- 日志字段：时间戳、操作者、源 IP、操作类型、资源对象、结果、请求 ID。
- 留存周期：生产 ≥ 365 天，审计归档 ≥ 3 年。
- 完整性：日志写入后不可修改，异步转发至审计中心集中存储。
- 告警：连续失败认证、越权访问尝试、大批量数据导出触发实时告警。

## 8. 漏洞管理流程

1. **发现**：CI 流水线 Trivy 镜像扫描 + 依赖 SCA（Dependabot）+ 月度漏扫 + 外部情报订阅。
2. **定级**：CVSS v3.1 评分，Critical ≥ 9.0 / High 7.0-8.9 / Medium 4.0-6.9 / Low < 4.0。
3. **修复 SLA**：Critical 72 小时、High 7 天、Medium 30 天、Low 90 天。
4. **验证**：修复后回归扫描 + 渗透测试抽验。
5. **复盘**：Critical/High 漏洞须出具根因分析报告（RCA），更新安全基线。

## 9. 密钥管理合规专章（SM-Config-KMS 专用）

### 9.1 等保密码模块要求
- 本服务作为密钥管理服务（KMS），须满足 GB/T 39786-2021《信息安全技术 信息系统密码应用基本要求》第三级及以上密码模块要求。
- 密钥全生命周期（生成、分发、存储、轮换、销毁）须在经过认证的密码模块内完成，禁止在应用层以明文形式处理密钥。
- 密钥存储须采用国密 SM4 硬件加密或经过国密局认证的软件密码模块（GM/T 0028 二级及以上）。

### 9.2 GM/T 0028 密码模块标准遵循
- 本服务密码模块遵循 GM/T 0028《密码模块安全技术要求》，覆盖以下安全域：
  - **密码模块规格**：硬件/软件/固件类型、密码算法（SM2/SM3/SM4/SM9）、接口规范。
  - **密码模块接口**：明确用户角色（密码管理员、安全 officer、加密操作员）与接口权限分离。
  - **软件/固件安全**：模块加载与升级须经数字签名验证，防篡改。
  - **操作环境**：进程隔离、内存保护、调试接口关闭。
  - **物理安全**（硬件模块）：防拆、防探针、防侧信道。
  - **密钥管理**：密钥生成（随机源熵 ≥ 256bit）、分发（SM2 密钥协商）、存储（加密保护）、销毁（多次覆写）。
  - **自评估与合规**：每年至少一次密码模块自评估，保留评估记录备查。

### 9.3 密钥轮换与审计
- 主密钥（KEK）轮换周期不超过 12 个月，数据加密密钥（DEK）轮换周期不超过 90 天。
- 所有密钥操作（生成、使用、轮换、销毁）须记录不可篡改审计日志，保留期不少于 3 年。
- 密钥导出须经双人授权（4-eyes），并记录导出原因、范围、回收时间。
